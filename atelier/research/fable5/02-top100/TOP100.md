## How the list was built

1. Seeded ~127 candidates across the 11 required categories from prior knowledge, then checked each against live GitHub data.

4. **Excluded** anything malware-adjacent, credential-stealing, or deepfake-abuse-oriented.
5. Ranked 1–100 strictly by real star count (descending). Stars are a popularity proxy, not a quality verdict — the narrative below is the quality verdict.

## 1. LLM Routers / Gateways

This is the load-bearing wall of BYOK. The user's OpenAI, Gemini, Anthropic and Ollama keys must resolve through one interface so every downstream module is provider-blind. **LiteLLM** is the pragmatic default — it is simultaneously a Python SDK and a self-hostable proxy with virtual keys, budgets and spend tracking, which means the keyring and the quota system can be one component. **one-api** is the best reference for token-accounting UX (it built a whole economy on it), **Portkey Gateway** and **bifrost** are the performance/edge plays, and **Vercel AI SDK** is how the *frontend* stays provider-blind while streaming. `aisuite` and `simonw/llm` round it out as minimal-embed and CLI-harness options.

## 2. Agent Frameworks

The conductor needs durable, resumable, interruptible orchestration — a design job is a long-running graph (brief → moodboard → generations → critique → composite), not a chat loop. **LangGraph** is the strongest fit: checkpointed state, human-in-the-loop interrupts, streaming. **pydantic-ai** supplies the typed contracts every artifact should be validated against. **MCP servers** matter strategically: exposing each spoke as an MCP server makes the studio drivable by any MCP-capable client (Claude, Cursor, Cherry Studio) for free. `openai-agents-python` and `google/adk-python` are the provider-native paths for the two mandatory key types; AutoGen/CrewAI/MetaGPT are mined for multi-agent critique and role-SOP patterns rather than adopted wholesale. **CopilotKit** is the odd-but-important one: it is the best open bridge between an agent runtime and an in-app canvas UI.

## 3. Image Generation UIs & Engines

**ComfyUI is the center of gravity.** Its node-graph JSON is a *serializable, versionable, agent-writable* representation of any generation pipeline, and its API makes it the ideal headless spoke — every important open model (FLUX, Qwen-Image, SD3.5, Wan) ships ComfyUI support on day one. A1111 stays for its installed base; Fooocus for its prompt-expansion UX; InvokeAI for its layered-canvas architecture (the closest OSS analog to Lovart's canvas-editing loop); krita-ai-diffusion as proof that "pro tool front-end + ComfyUI back-end" works. The utility tier (rembg, Real-ESRGAN/upscayl, IOPaint) provides deterministic post-processing every design pipeline needs. **Qwen-Image** earns a slot specifically for text rendering — posters and packaging live or die on typography.

## 4. Video

Two different problems hide under "video": *generation* (diffusion models) and *composition* (assembling deliverables). For generation, **Wan2.2** is the Apache-2.0 workhorse (its 5B tier runs on consumer GPUs), LTX-Video is the fast-preview tier, HunyuanVideo the quality tier, FramePack the low-VRAM tier — all consumed through the same ComfyUI spoke. For composition, **Remotion** is the sleeper hit for a design agent: motion graphics as React components means the LLM can literally *write* branded video templates and the studio renders them deterministically from JSON props. **OpenCut** covers the human touch-up mile.

## 5. Audio

Audio splits into voice-in (STT), voice-out (TTS/cloning) and music/SFX. **whisper.cpp** gives local-first, key-free voice input ("talk to your canvas"). On the TTS side the 2025–26 generation is strong: **chatterbox** (MIT, watermark built in — good for client deliverables), **F5-TTS** for zero-shot cloning, **kokoro** for in-browser instant previews, GPT-SoVITS for few-shot character voices, fish-speech at the quality frontier (mind its research license). **AudioCraft/MusicGen** remains the practical open path for music beds — weights are CC-BY-NC, so commercial deployments should treat it as draft-only or use API music services.

## 6. 3D

3D in a design studio is mostly *asset generation* (image→mesh for product mockups) plus *display* (a viewport on the canvas). **Hunyuan3D-2** and **TRELLIS** are the quality generators, **TripoSR** the half-second draft tier; all export GLB straight into a **three.js / react-three-fiber** viewport node on the board. **blender-mcp** is strategically important: it demonstrated that an LLM can drive a full DCC over MCP, which is exactly the escape hatch a design agent needs for real 3D jobs. Note the license trap: the original **gaussian-splatting** code is research-only — ship MIT reimplementations (gsplat) instead.

## 7. Infinite Canvas / Editors

The board is the product. **tldraw** is the strongest foundation: a real SDK (not an app you gut), custom shape types, multiplayer sync, and a proven record of AI-canvas experiments ("make real"). Its license (free with watermark, paid to remove) is the honest cost of best-in-class. **Excalidraw** (MIT) is the fallback if license purity wins. **xyflow** is not the same thing — it's the *pipeline* canvas, ideal for the loom's editable generation graphs. Fabric/Konva/Pixi are lower-level engines if a custom deterministic layout renderer is needed (agent emits JSON → human tweaks → export SVG). **Onlook** and **AFFiNE** are architecture donors: design-to-code lane and local-first CRDT persistence respectively.

## 10. Local-First BYOK Studios

Nobody has shipped an open Lovart, but this category shows every piece has been solved somewhere: **LobeHub** is the closest existing product (multi-provider BYOK + artifacts + image gen + plugin marketplace); **LibreChat** has the best per-user encrypted key storage to copy for the keyring; **Open WebUI** the best self-host story; **Cherry Studio** the best desktop MCP integration; **AnythingLLM/Jan** the desktop-first local model lifecycle. **Ollama + llama.cpp** make "no key at all" a valid keyring entry. **Dify** and **n8n** sit at the platform end — Dify's workflow-node taxonomy is the best-tested vocabulary for what loom's palette should contain, and n8n is the delivery glue (publish finished assets everywhere).

## 11. Observability / Quota

BYOK makes cost transparency a *feature*, not plumbing: users burn their own keys, so per-canvas spend must be visible in the UI. **Langfuse** is the primary pick — OTel-based, self-hostable, with native LiteLLM/LangGraph callbacks, so traces and cost roll up per design job. **Helicone** is the zero-code alternative (proxy-based, with rate limiting = quota enforcement). **promptfoo** guards the conductor's prompts in CI; **Phoenix/opik** cover eval-heavy workflows; **OpenLLMetry/OpenLIT** are the OTel-native instrumentation layers, with OpenLIT adding GPU telemetry for the local diffusion spokes.
